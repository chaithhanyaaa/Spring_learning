CONTAINER:
-> a container is something that creates and manages the objects for you.
-> it is responsible for creating the objects and injecting the dependencies.

  Car car;
  public container(){
    car = new Car();
  }
  public Car getCar(){
    return car;
  }
}

Container container = new Container();
Car car = container.getCar();

--------------Spring vs Spring Boot----------------

SPRING:
-> Spring Framework is a core Java framework used to build enterprise-level applications.
-> Its main purpose is to provide Inversion of Control (IoC) and Dependency Injection (DI) so that applications are loosely coupled, maintainable, and testable.
-> In Spring, the developer has full control, but that control comes with a lot of manual configuration.
The developer must explicitly define configuration classes, component scanning, bean creation, dependency wiring, and other infrastructure details.
As the application grows, the amount of configuration also increases, making development slower and more complex.
-> Spring is powerful and flexible, but it requires significant setup effort, especially for beginners.

SPRING BOOT:
-> Spring Boot is an extension of the Spring Framework that aims to reduce boilerplate code and configuration.
-> It does not replace Spring; instead, it uses Spring internally and adds automation and sensible defaults.
-> Spring Boot provides auto-configuration, which means it automatically configures the application based on the dependencies present in the classpath.
-> With Spring Boot, developers can quickly create and run applications with minimal configuration, allowing them to focus more on business logic rather than setup.
-> Spring Boot is ideal for microservices and rapid application development, while Spring Framework is better suited for complex applications that require fine-grained control over configuration.
